# Alice：127 → 192 成员与项目迁移运行手册

## 目标

把本机 `127.0.0.1:3100` 中的公司成员、组织关系、项目、任务和技能迁移到 `192.168.72.157:3100`，并保留服务器上运行的 Alice。

## 已确认的产品约束

- 使用官方 `company export` / `company import` 可移植包，不直接复制数据库。
- 项目、任务和技能不是默认导出项，必须显式指定。
- 导出包不会包含密钥，也会移除本机路径；环境变量只会形成待补配置声明。
- 导入的智能体默认关闭定时心跳，不会在导入后自行开始执行任务。
- 目标是导入到服务器现有公司，不新建第二家公司。

## 执行门禁

开始前必须同时满足：

1. Jack 明确授权本次连接 `127` 和 `192`。
2. 源端和目标端版本、数据库迁移状态均正常。
3. CLI 已分别持有源端与目标端的控制面凭据；不得在命令或日志中打印令牌。
4. 服务器现有公司已完成迁移前备份。

## 执行流程

### 1. 只读预检

- 查询源端公司、成员、项目和任务数量。
- 查询目标端现有公司和 Alice 的身份、运行位置、状态。
- 记录源端与目标端 ID 映射，不使用历史 ID 猜测。

### 2. 备份目标端

先把目标公司导出到带时间戳的空目录，包含：

```text
company,agents,projects,issues,skills
```

备份完成后检查 `COMPANY.md`、`.paperclip.yaml` 和文件数量；备份目录只读保留到迁移验收完成。

### 3. 导出源端

源端导出同样显式包含：

```text
company,agents,projects,issues,skills
```

导出后核对：

- 成员数量与组织关系；
- 项目及任务数量；
- 技能包与引用；
- 环境输入声明中不含真实密钥。

### 4. 目标端预演

先使用 `--dry-run` 导入到目标现有公司。默认使用 `rename` 冲突策略，避免覆盖服务器 Alice。

预演必须人工检查：

- Alice 不会被替换或重命名；
- 其他成员没有意外重名；
- 项目、任务、父子关系和负责人映射完整；
- 没有未知技能策略版本或阻断错误。

存在冲突时停止，不直接改用 `replace`。

### 5. 正式导入

仅在预演无阻断后执行一次正式导入。命令在当前终端前台运行，不创建循环脚本、后台窗口、自动重连或定时重试。

### 6. 重新连接本机智能体

- 为每个本机智能体在目标端创建新的 API 密钥。
- 将运行地址改为 `http://192.168.72.157:3100`。
- 本机成员逐个连接、逐个验证；服务器 Alice 保持服务器运行。
- 不复用源端令牌，不把令牌写入仓库、任务评论或迁移包。

### 7. 验收

迁移完成必须同时满足：

- 目标端成员、项目、任务、技能数量与源端及冲突处理结果一致；
- Alice 仍在服务器运行，本机成员从本机连接目标端；
- 任取一个成员可领取测试任务、回写状态和评论；
- 重启客户端后不会弹出循环终端窗口；
- 源端保持不变，直到 Jack 确认目标端可作为唯一协作入口。

## 回滚

若正式导入后验收失败：停止派发新任务，保留源端继续使用；依据迁移前目标端备份恢复或清理本次新增记录。未完成验收前不删除源端数据。
